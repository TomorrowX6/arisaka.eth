# Minecraft 1.12.2 and Firefox desktop applications

The Plasma 6 / Breeze Dark desktop gains real Minecraft 1.12.2 and Firefox applications in the desktop, application launcher, search, and Discover. Opening either app creates one native window. Minimize, maximize, resize, virtual desktops, and task switching retain the running instance. Closing cancels loading and releases the iframe and its engine.

Minecraft uses the Eaglercraft 1.12.2 u3 offline distributions linked by https://dev.eaglercraft.com/p/downloads. A separate `arisaka-desktop-apps` Cloudflare Worker serves reproducibly extracted, hash-pinned assets. The WebAssembly GC build is preferred; a JavaScript compatibility build is selectable. Each file stays below Cloudflare's 25 MiB static asset limit by externalizing the EPW/EPK payloads and gzip-compressing the large JavaScript source. No arbitrary reverse proxy, uploaded content, or access to CTF APIs is added. World databases, resource packs, and settings are namespaced by the active desktop profile. Users create, play, save, export, and reopen worlds through Minecraft's actual interface.

Firefox uses the actual Gecko WASM application published by HeyPuter at https://developer.puter.com/labs/firefox-wasm/. This distribution and its supported WISP networking service were verified together: Gecko 153.0a1 boots and loads an external website. The official endpoint omits the CORP header needed for ordinary embedding; a credentialless iframe under a cross-origin-isolated desktop works, including SharedArrayBuffer and JSPI. Its storage is temporary for the lifetime of the desktop page. A compact temporary-session label and independent-open link provide the relevant controls; the user requested removal of note paragraphs and unrelated UI text. Do not claim the embedded profile survives a desktop reload. Keep the official engine's user-gesture Launch Firefox step. Show a useful compatibility message before downloading when JSPI or credentialless iframes are unavailable.

The desktop keeps its strict CSP and adds only the configured runtime origins to `frame-src` and the cross-origin-isolation permissions policy. COOP/COEP headers enable Firefox without changing the JavaScript/Python runner restrictions. The Minecraft iframe has a separate origin, a sandbox, and an origin/source/channel-checked status message interface; no CTF credentials or private artifacts cross that boundary. No runtime downloads occur on desktop boot or merely opening the launcher. Previews must never instantiate another iframe.

The current 26-case campaign, server verification, entrance token, edition, secrets, and unrelated user playlist remain unchanged. Deployment is authorized by the existing conversation: deploy the runtime assets first, verify them, then deploy the desktop, push the feature branch, and update PR 13 without merging it.

Validation includes deterministic extraction and integrity failures, asset/header tests, loading/closing/minimize lifecycle checks, real Minecraft menu/world save/reopen checks, real Firefox address-bar navigation and rendering, and the existing Worker and 26-case browser suites. Heavy upstream runtime tests are a separate explicit command so ordinary CI does not depend on the availability of Puter's demo or download hundreds of megabytes on every shell test.
